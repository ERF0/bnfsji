### A. Cloudflare-first custom JavaScript application — selected direction; deployment details pending

- Cloudflare Workers with React Router/Vite for the Arabic/English web app and server APIs; use ordinary `.js`/`.jsx` as explicitly selected by the founder.
- Supabase Auth and PostgreSQL as identity and commerce system of record, with strict RLS and explicit server authorization. Benchmark Hyperdrive connected to Supabase's direct database endpoint against an RLS-backed Data API approach; Supabase transaction pooling is a separate alternative only with a compatible driver and verified transaction behavior. No path is approved.
- R2 for product media if cost/operations testing supports it; Cloudflare Queues/Workflows for retryable asynchronous work; Cloudflare observability for Worker telemetry.
- Rust/Wasm owns the production quote-calculation domain: integer JOD fils, commission, delivery charges, and total invariants. This is selected for a single authoritative financial rule implementation, not an unmeasured performance claim. Keep order/payment records authoritative in PostgreSQL.
- Multi-seller checkout writes one buyer order and seller suborders atomically, records immutable price/fee snapshots, reserves stock, and schedules fulfillment. Final order delivery and dispute state control payout eligibility; provider reconciliation remains a separate state transition.
- Main benefit: closest fit to the Cloudflare/Supabase/Rust/JavaScript constraints and lower starting infrastructure cost. Main cost: Bnafsaji-specific marketplace operations and the full 61-category scope must be built and verified rather than inherited from a marketplace engine.

Cloudflare documents React Router as a full-stack Workers path and recommends its Hyperdrive integration use Supabase's direct connection endpoint, with Hyperdrive providing connection pooling. Supabase's own transaction pooler is a separate serverless option with documented limits on prepared statements and query pipelining. Rust-on-Workers is supported through `workers-rs`/Wasm, with bundle size and startup time to measure. These documents do not prove Bnafsaji compatibility; a real Worker-runtime staging test is required.

**Research snapshot (2026-10-21, before implementation):** the repository had no Rust workspace or quote implementation. ## Current cost floor and reliability notes

The current priced baseline, JOD conversion, service allowances, unknown communications costs and conditional PITR scenario are summarized in the [operating-cost envelope](../operations/OPERATING_COST_BUDGET.md), checked 2026-10-22. It is a planning estimate, not a measured bill or approval to purchase.

- Cloudflare Workers Paid starts at $5/month and currently includes 10 million Worker requests and 30 million CPU milliseconds monthly; excess is usage-billed. Static asset requests and egress are treated differently from dynamic Worker requests. This is a pricing floor, not capacity proof.
- Supabase Pro is $25/month. Each project has its own Postgres compute instance; the $10 monthly compute credit covers one Micro instance. A separate staging project adds about $10/month for its Micro instance, so a minimal two-project Pro setup plus Workers Paid is about **$40/month** before usage/overages and every third-party/provider cost. Compute size must be proven by load tests.
- Supabase Pro currently includes 8 GB database disk, 250 GB egress, and 7-day daily backups. Point-in-time recovery starts at $100/month per 7-day retention. Proposed RPO/RTO must be matched to an affordable recovery design and proven restore drill; backups alone are not evidence of restore capability.
- **Jordan latency/data-location check (official region list rechecked 2026-10-22):** Supabase says each project has one primary region and stores project data there; the published general and exact region lists show no Jordan region. Frankfurt is the closest listed candidate for an Amman launch, but actual API/database round-trip time must be measured from Jordan networks and the chosen Worker/database connection path before approving latency targets. Supabase explicitly says region selection controls data location but does not prove regulatory compliance; counsel must review transfer and residency obligations before a non-Jordan region is selected.
- **Jordan data-protection gate:** The Ministry of Digital Economy and Entrepreneurship lists the Personal Data Protection Law No. 24 of 2023 and 2025 implementing materials. Article 11 requires a DPO if the controller's primary activity processes personal data, or if it processes sensitive data, data of people lacking legal capacity, financial information, or transfers databases outside Jordan. Given marketplace accounts and payment records, DPO appointment appears likely applicable, but counsel must confirm Bnafsaji's controller role and exact triggers. The official controller/processor/DPO register instructions require the controller to enter required information within 30 days after actual processing begins, and update changed information within 15 days; confirm registry launch and filing procedure with the Ministry/counsel. The 2025 Security, Technical and Organizational Measures Instructions require a DPIA for sensitive-data processing or transfers outside Jordan; they also cover security reviews, encryption, backups/restoration, retention, deletion, and processor/subprocessor contracts. If a non-Jordan Supabase region is selected, counsel and the DPO must approve the transfer basis, DPIA, notice/consent, vendor terms, subprocessor list, retention/deletion, and incident process before launch. Applicability to the precise Bnafsaji data flows still needs legal review.
- **Reliability recommendation for founder approval:** set an initial 99.5% monthly application availability objective, measured by external synthetic checks of browsing, checkout readiness, and order status; target RPO <=2 minutes and RTO <=4 hours for the production database. These are proposed operating objectives, not vendor commitments. The Pro plan does not include Supabase uptime SLA; Cloudflare Pay-as-you-go/Free support has no SLA. Supabase PITR is required for a seconds-level RPO, starts at $100/month for seven days, and requires at least Small compute. Relative to the two-project + Workers baseline above, this makes the rough starting total about **$145/month** (PITR $100 + production compute increase from Micro to Small, about $5), before usage and integrations. Daily backups alone can mean up to 24 hours of data loss. Supabase says restore duration varies with database/WAL size and project availability is interrupted during restore, so the 4-hour RTO is unproven until a timed restore drill. Supabase database backups also exclude Storage objects; media recovery needs a separate tested plan. If the founder prioritizes the ~$40 baseline instead, the RPO must be relaxed to daily-backup recovery and explicitly accepted as a commerce risk.
- Cloudflare R2 includes 10 GB-month, 1 million Class A, and 10 million Class B operations before usage charges. Product media volume and transforms need an image corpus and traffic model.
- For founder budget framing, the Central Bank of Jordan listed USD at 708–710 fils on 2026-10-22. Refresh the exchange rate and vendor prices when the budget is approved.
